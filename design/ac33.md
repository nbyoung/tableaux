# Design ac33: Agent identity

This design resolves the three findings that remain under `ac33` after F20 and F24 landed. **F1:** an agent commits under its own identity, a person's commit that names an agent in `Co-Authored-By:` stays the person's act, and the audit reports an agent's work recorded under a person's identity (decisions 1 to 3). **F10:** an optional `agents.yaml` lists the identities that are agents, and without it a junction that pairs an email with a `model` makes that email an agent's (decisions 4 and 5). **F2:** an agent with no stated reviewer takes the nearest person among the assignee and the authorities, `reviewer: false` waives review, and both apply from the language version that introduces them, read at each commit (decisions 6 to 9). The language rises by a minor version, 0.4.0, composed with the siblings' (decision 10).

## F1 Agent identity in commits

**The problem.** README.md#junctions identifies the contributor "like the assignee, by commit email" ([README.md:65](../README.md#junctions)), and README.md#tasks identifies the assignee "by the email address they commit with" (line 51). PLAN.md's F1 ([PLAN.md:216](../PLAN.md#findings)) notes that an agent in a person's session commits under that person's identity, so the history credits the person. SYNTAX.md ([line 548](../SYNTAX.md#commit-trailers)) already says a tool reads `Model:` and `Co-Authored-By:` together "to see agent work whoever the author is", but no rule says what such a commit counts as. The evidence is mixed. On the umbrella's `main`, 107 of 180 commits are the agent's own, `<display name> <noreply@anthropic.com>`. Of the owner's 73, 50 carry an agent `Co-Authored-By:` and 44 a `Model:`: these are the owner's reviews, merges and pin advances, which the dispatcher drafted. In the four subprojects, nine owner commits record agents' design gates with both trailers, for example tablo `39ed778` and tablotui `d93b9b6`.

**The rule.**

1. Every participant, person or agent, is identified by the email address it commits with. An agent commits under its own identity and never under a person's. One identity may serve several models, since the `Model:` trailer records which one ran. D3's `noreply@anthropic.com` is therefore the agents' own identity, and the practice of the effort since 2026-09-30 is the rule.
2. A person who commits with an agent's help names the agent in `Co-Authored-By:`. The commit stays the person's act. Its event's actor is the author, and it counts as the person's work, record, review and authorisation. A view marks the agent's part. The trailer never makes the agent the actor, since the method identifies by author email alone. The owner's 50 co-authored commits therefore keep their effect: the plan commit `6b6c99a` authorises, and each "Accept the … mockups" merge reviews.
3. A tool tells an agent's identity from a person's by F10's rule below, never by an email convention and never by the `Model:` trailer, which the owner's own commits carry.
4. The audit reports a commit **at** an agent's junction, as README.md#junctions defines "at", whose author is a person and which carries `Model:` or a `Co-Authored-By:` that names an agent. The agent's work then reads as that person's. A commit that only carries `Reviewed:` is at no junction, so the owner's co-authored acceptances stay silent. So does a merge that brings in an agent's status, since it changes no path against every parent.

**Examples.**

```
Record the node firmware at its unit gate          # author ben@example.org; c07d's unit junction names opus

Model: claude-opus-5-5
Co-Authored-By: Opus <opus@example.org>             # H7: opus's work, recorded as ben's
```

```
Accept the global tableau mockups                   # author nbyoung@nbyoung.com; no junction: silent

Reviewed: ab8e mockup
Reviewed: 32e7 mockup
Model: claude-opus-5-5
Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

**The text change.** [`README.md.diff`](ac33/README.md.diff) adds one paragraph to Roles, which states rules 1 to 4, and makes the assignee "the person or agent responsible". [`SYNTAX.md.diff`](ac33/SYNTAX.md.diff) rewrites the trailers paragraph and adds a `Co-Authored-By: <name> <email>` row: the method reads it only where the email is an agent's. [`VIEWS.md.diff`](ac33/VIEWS.md.diff) adds the co-author to the Models fact. It also corrects the viewer sentence: an agent commits as itself, but a tool it runs in a person's session may read the person's email, so a dispatcher still names it by `person`.

**The audit rule.** H7, warning: "A commit at an agent's junction whose author is a person and which carries a `Model:` trailer or a `Co-Authored-By:` trailer that names an agent; a commit at which `version.yaml` states a language before 0.4.0 is exempt." Its source is the Roles paragraph, and its entry is `agent-work-under-person`. Like H6, nothing resolves it, since a commit does not change, and the audit lists it as information once its junction is historical (VIEWS.md#audit). The exemption keeps the nine subproject commits silent, as H6's keeps the history before F20 silent.

**What tablo does today.** `snapshot.go:799` passes only `Authorised`, `Reviewed`, `Reaffirmed` and `Model` to the Validator, so `Co-Authored-By:` never reaches a rule. `internal/derive/events.go:434` reads `Model:` alone. `internal/validate/derived.go:354-398` applies H3 to any commit at a model junction and H6 only to the contributor's own commit, so a person's commit at an agent's junction passes both silently. What changes: `snapshot.go` carries `Co-Authored-By`. `internal/validate` gains `h7` beside `h6`, with the author's kind from the Derivation. `internal/validate/rules.go` and `internal/audit/rules.go` gain the H7 row.

**What the front ends meet.** The history view marks a co-authored commit with the agent and its model, at detail, beside the models it already shows.

**The version effect.** None alone: a trailer Git already carried gains a reading, and the rule is a warning. It rides on the minor version that F10 and F2 raise, and it names that version for its exemption.

**The alternative.** Reading `Co-Authored-By:` as making the agent the actor loses: the owner's co-authored reviews and the plan commit would stop counting, and every task would turn proposed. An email convention such as `noreply@` loses because a vendor chooses it, not the project.

## F10 An agent as assignee

**The problem.** PLAN.md's F10 ([PLAN.md:227](../PLAN.md#findings)) notes that only a junction carries `model`, so README.md#roles defines an agent as "a contributor at a junction that states a `model`" ([README.md:166](../README.md#roles)). An agent assignee's default junction then looks like a person's. In `junction-kinds`, `a300` is assigned to `bot`, and its default junction resolves as a person's plain junction with no reviewer. F2's nearest person needs every authority's kind, and the files state no authority's kind at all.

**The rule.** An identity is an agent's when `agents.yaml` lists it. In a project without that file, an identity is an agent's when a junction states it as contributor beside a `model`. Every other identity is a person's. A contributor whose identity is an agent's is an agent at every junction, with or without a `model`: a view shows 🤖, and the default reviewer applies. A project that keeps the file lists every agent there. The files at a commit judge the commit, so the kind, like the reviewer, reads the files at each commit (tablo `27a3` decision 2).

The file holds email addresses only. It holds no name, which Git carries. It holds no model, because one identity runs many: under D7 `noreply@anthropic.com` runs `claude-haiku`, `claude-sonnet`, `claude-opus` and `claude-fable`. It holds no person, since every identity it omits is a person's. The README.md#junctions sentence "A model names no one, so an entry that states a `model` states its `contributor` beside it" stands unchanged, and so does J5. A model still names no one and still stands beside its contributor in one entry, and the file names who is an agent, not what any agent runs.

**Examples.**

```yaml
# agents.yaml — the identities that are agents
agents:
  - noreply@anthropic.com      # every Claude model; the Model: trailer tells them apart
```

`agents-listed` lists `opus@example.org` and assigns it a leaf whose file states no junction. Its plain default resolves to `{ contributor: opus@example.org, reviewer: olive@example.org }`: the default junction is an agent's, and the nearest person reviews it.

**The text change.** [`SYNTAX.md.diff`](ac33/SYNTAX.md.diff) adds `agents.yaml` to the layout tree and table as "Fixed; optional", with its own section: schema, fields and example. The schema is a mapping with one required field, `agents`, a non-empty list of distinct email addresses. [`README.md.diff`](ac33/README.md.diff) states the kind rule in Roles and rewrites the agent bullet. [`schemas-agents.schema.yaml.diff`](ac33/schemas-agents.schema.yaml.diff) is the derived schema file.

**The validator rules.**

| Id | Severity | Rule | Source | Entry |
|----|----------|------|--------|-------|
| A1 | error | `agents.yaml`, when present, matches its schema | SYNTAX agents schema | `agents-not-email` |
| A2 | error | When `agents.yaml` exists, every contributor that a junction states beside a `model` is one it lists | README Roles: "a validator rejects a junction that states a `model` beside a contributor the file does not list" | `agents-unlisted-model` |
| L4 | warning | Amended: `agents.yaml` joins the paths the layout names | SYNTAX Layout table | `file-stray-path` |

A2 is an error because the two files then state one fact two ways, as J17 says of a `commit` that contradicts its pin. A2 also guards F2: removing an agent from the file, which no task authorisation covers, cannot make that agent a person while a junction still pairs it with a model.

**What tablo does today.** `internal/load/source.go:47-65` knows four file kinds and reports `agents.yaml` as stray (L4). `internal/derive/junction.go:85-88` draws 🤖 only where `Model` is stated, and `internal/derive/tree.go:182` grants the agent role on the same test. What changes: `internal/load` gains the file kind. `internal/validate/schema.go` embeds `agents.schema.yaml` and maps its errors to A1, and a files rule gives A2. `internal/derive` gains a kind per email, from the file or the pairing, read at each commit, and `Marks` and `Roles` test the kind.

**What the front ends meet.** An agent's junction may state no model. A brief (tabloio `e4c7`) then leaves the model line empty, so the dispatcher chooses, and the assignment view lists such an agent with no model.

**The version effect.** Minor: a file appears that older content satisfies by its absence.

**The alternative.** A `model` on the task loses. Kind belongs to the identity, so the same email would be an agent on one task and a person on the next. This plan would also write `model: claude` on twenty-seven tasks only to say "agent", which matches every model and lets H3 say nothing. An identities file with a name, a kind and a model for each email loses because its model contradicts D7 and its person entries restate the default.

## F2 Review of an agent under an agent

**The problem.** README.md#junctions reads "An agent contributor with no stated reviewer takes the assignee as reviewer" ([README.md:65](../README.md#junctions)), and Roles adds "its work at the gate always has a reviewer" (line 166). When the assignee is an agent, the agent reviews itself, as `a300` in `junction-kinds` does at K8. When the assignee is a person, no entry can remove that person's review, nor a reviewer an ancestor states. PLAN.md#review-policy relies on the first case: agent-assigned subtrees "review themselves at the execution gates" ([PLAN.md:146](../PLAN.md#review-policy)).

**The rule.**

1. **The default.** An agent contributor with no stated reviewer takes the nearest person among the task's assignee and its authorities. That is the assignee when the assignee is a person, otherwise the nearest authority who is one, and the assignee when none is. A person's plain junction with no stated reviewer still has none.
2. **The waiver.** `reviewer: false` waives review: the junction has no reviewer whoever contributes. The value inherits field by field as a stated reviewer does, so a parent's waiver reaches its subtree, and a descendant restores review only by stating a reviewer of its own. A junction that states no reviewer differs in two ways: it takes the reviewer an ancestor states, and an agent's junction takes the default above. The waiver needs no rule of its own beyond the schema, since an authority accepts it as part of the task file. The audit's sole review, which the owner made a finding as information on 2026-10-07, still lists a waived junction.
3. **The version.** A project whose `version.yaml` states a language before 0.4.0 reads a contributor as an agent only where its junction states a `model`, and gives that agent the assignee as reviewer. A tool reads the version at each commit, as it reads the files there (`27a3` decision 2), so a review that the older language accepted stays accepted after the version rises.

**Examples.** `junction-review-waived` puts the umbrella's choice B in miniature:

```yaml
# tasks/e4a1.yaml — the root sends design to an agent and waives its review for the whole tree
junctions:
  design: { contributor: bot@example.org, model: claude-fable, reviewer: false }
# tasks/b2c9.yaml states nothing: bot records design, and no Reviewed: commit is owed
# tasks/c3d8.yaml restores the review:
junctions:
  design: { reviewer: pat@example.org }
```

`review-nearest-person` puts `b2c9` under `c5f0`, both assigned to `bot`, under the root `olive`. Its design junction resolves to the reviewer `olive@example.org`, which skips both agents. Its sibling `d3a6`, assigned to `pat`, resolves to `pat`. At N2, under 0.3.1, `bot` reviews `b2c9` itself. Olive raises the language at N3, and N2 still accepts the junction at the tip.

**The text change.** [`README.md.diff`](ac33/README.md.diff) replaces the default sentence and adds the waiver and the version rule in Junctions. It also amends "the plain default" to read "nobody reviews it but the nearest person where the assignee is an agent". It rewords the assignee, agent and reviewer bullets in Roles. In Status it drops "as an agent is at a junction that states none", which the default no longer makes true in general. [`SYNTAX.md.diff`](ac33/SYNTAX.md.diff) gives `reviewer` the schema `{ oneOf: [{ $ref: "#/$defs/email" }, { const: false }] }` and the fields row its meaning.

**The validator rule.** T4 is amended to read "`reviewer` may instead be `false`, which waives review". `junction-reviewer-true` shows that only `false` waives. S11, H2, H4 and H5 read the reviewer as the Derivation resolves it, and their wording stays.

**What tablo does today.** `internal/derive/junction.go:337-343` gives the assignee as reviewer wherever `Model` is stated. `internal/model/model.go:123` holds the reviewer as a string field. `internal/validate/schema.go:312-313` reports `reviewer: false` as T4 and still resolves the string `"false"` as a reviewer, so S11 then fails "whose reviewer is false". `internal/derive/review.go:77-133` already judges each `Reviewed:` commit by the junction as the files stand at that commit. What changes, in `internal/derive` (`27a3`): `resolve` treats a stated `false` as a stated empty reviewer that stops inheritance; the default walks the assignee and the authorities for the first person; `Field.By` gains a supplier for that person beside `ByAssignee`, so `DefaultMarks` still draws no inherited review on a parent; the version at the commit chooses the reading. In `internal/model`, the plain entry records the waiver.

**What the front ends meet.** The brief and the task view name the reviewer's supplier, which may now be "the nearest person, assignee of `<task>`" or "waived by `<task>`". The waived mark is the contributor's alone, as for a self-review, and needs no symbol.

**The version effect.** Minor: a field value appears that older content satisfies. Rule 3 keeps the meaning of every project that states an earlier language.

**The alternative.** Keeping the assignee default and adding only the waiver changes no cell. But an agent assignee would still review itself by default, and F2's first case would persist wherever a plan forgets the waiver. Without rule 3, the tool would read every commit with the new default. Each agent self-review in this plan would turn into a review from the wrong hand, and five statuses (`c2ad`, `e9c6`, `e3cb`, `fcec`, `7861`) would fail S11 at the raise.

## Meeting points

## Decisions at review

1. **An agent commits under its own identity, and one identity may serve several models.** D3's `noreply@anthropic.com` is that identity. The alternative gives each model its own email, which the `Model:` trailer makes redundant and every model revision would change.
2. **A person's commit with an agent co-author stays the person's act,** as work, record, review and authorisation, and the trailer only marks it. The alternative reads it as the agent's work, which strips the owner's 50 co-authored commits of their reviews and the plan commit of its authorisation.
3. **H7, a warning,** for a person's commit at an agent's junction that carries `Model:` or an agent's `Co-Authored-By:`, exempt before 0.4.0. The alternative is information, which the audit's default hides.
4. **F10 by `agents.yaml`: a list of emails, optional, with the pairing as fallback.** The alternatives are a task-level `model` or a mapping of name, kind and model, whose model contradicts D7.
5. **A1 and A2 are errors.** The alternative makes A2 a warning, and the kind of an unlisted email paired with a model is then undefined for F2.
6. **The default reviewer is the nearest person among the assignee and the authorities, and the assignee when none is a person.** The alternative keeps the assignee and adds only the waiver.
7. **The waiver is `reviewer: false`, inherited as a stated reviewer is.** The alternative is a separate `review: false` field, which needs a rule for its combination with `reviewer` and an inheritance of its own.
8. **The new reading applies from 0.4.0, judged by the version at each commit.** The alternative applies it everywhere at once, and five of the umbrella's statuses, with every agent-assigned status in the four subprojects, then fail S11 at the raise.
9. **The umbrella states choice B,** [`plan.diff`](ac33/plan.diff): the root waives the four execution gates, and the three method decisions restate the owner at implementation. The alternative, A, leaves the plan as it stands and gives the owner every future agent execution review, here and in each subproject when its language rises.
10. **The language rises by a minor version, 0.4.0, composed with 9f3f's,** and `version-minor-ahead` moves to 0.5.0. The alternative is a patch, which a new file and a new field value do not allow under README.md#version.
